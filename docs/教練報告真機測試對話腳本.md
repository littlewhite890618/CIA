# 教練報告真機測試對話腳本

用途：手動真機測試時，用一組對話盡量涵蓋所有訊號類型，驗證教練報告的內容
是否完整、正確引用原句。訊號的完整定義見 [即時訊號判定準則.md](即時訊號判定準則.md)，
本文件只列測試用的具體對話內容與傳送順序。

## 使用方式

1. 依下表順序傳送訊息給晴晴，等她回覆後再傳下一則（除非備註寫「緊接」）
2. 傳完最後一則後停手，等待靜默門檻（預設 25 分鐘）觸發邀請
3. 點擊「看這次的回饋」按鈕，對照報告內容與下表逐項檢查

**順序原則**：先讓正向互動（H 開頭）建立起來，中段做句點與連發測試，
**地雷（L 開頭）留到最後**——地雷會讓晴晴依人設卡的邊界反應變冷淡，
放在前面會影響後面測試的互動品質。

## 刻意沒放進去的項目

- **L3（前三次對話約見面）**：只在與該角色的前三次對話才算地雷（`app/dialog/signals.py`
  的 `apply_session_rules`）。測試帳號多半早已聊過三次以上，放進去也不會被標記，
  故略過。若要測 L3，需用全新的使用者帳號在前三次對話內測試。
- **L10 的觸發條件是程式判斷，不是模型**：只要第 4–6 則真的在 30 秒內
  （`SIGNAL_BURST_WINDOW_SECONDS`，可調）連續送出、中間晴晴沒插話，就會命中，
  不需要糾結內容語意對不對。

## 額度提醒

19 則訊息全部跑完，會產生 19 次 dialog 路徑呼叫（晴晴的即時回覆）+ 1 次 analysis
呼叫（話題萃取）+ 1 次 analysis 呼叫（訊號偵測）+ 1 次 coaching 呼叫（報告生成），
dialog 路徑額度消耗較大，測試前留意當日額度是否還夠——直接觀察伺服器 log 的
`LLM 呼叫完成` / `LLM 呼叫失敗` 記錄最準確，第一則回覆若明顯像罐頭語句
（例如「欸我剛剛恍神了一下」），代表已經在走降級回應，額度可能已經用盡。

## 驗收對照

收到報告後，對照：

1. 「做得好」是否提到 H1～H4 對應的內容
2. 「可調整」是否提到 K1～K3、L4～L9 裡至少幾項具代表性的地雷/句點
3. 報告裡的引述是否對得上你實際傳的原句（見
   [即時訊號判定準則.md](即時訊號判定準則.md) 的「判斷依據要引用訊息內容」規則）
4. 若同一場對話裡出現過「上一句是哪句」容易混淆的情境（例如連續多個
   「嗯」），檢查報告有沒有歸因到錯誤的對話內容——這是 2026-09-24
   真機測試發現過的問題（訊號偵測把使用者的敷衍回應歸因到錯誤的角色提問），
   已修正 `app/dialog/signals.py` 的 `format_transcript()` 合併角色連續泡泡，
   此表也可用來驗證修正是否生效
