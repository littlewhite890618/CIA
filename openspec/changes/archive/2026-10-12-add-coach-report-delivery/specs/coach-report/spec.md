## Purpose

讓使用者在一段對話結束後，能在自己同意的前提下取得該次對話的溝通回饋，使累積的行為訊號轉化為可理解、可行動的建議，並確保報告在平台限制下仍可送達或補救。

## ADDED Requirements

### Requirement: 對話結束後的回饋邀請

系統 SHALL 在 session 因靜默而結束後，以該角色的身分送出一則邀請訊息，詢問使用者是否要查看本次對話的回饋。每一個 session MUST 至多邀請一次。

#### Scenario: 對話靜默結束後發出邀請

- **WHEN** 一個 session 因靜默達門檻而被標記為結束
- **THEN** 系統送出一則邀請訊息，並記錄該 session 已發送邀請

#### Scenario: 不重複邀請

- **WHEN** 背景輪詢再次掃描到一個已發送過邀請的 session
- **THEN** 系統不再送出邀請

#### Scenario: 互動過少的對話不邀請

- **WHEN** 一個結束的 session 其使用者訊息數未達可供分析的下限
- **THEN** 系統不送出邀請，並記錄略過的原因

#### Scenario: 邀請時訊息視窗已逾期

- **WHEN** session 結束時平台訊息視窗已逾期
- **THEN** 系統不呼叫平台發訊 API，將該 session 標記為未能邀請並記錄原因

### Requirement: 使用者同意後才生成報告

系統 SHALL 僅在使用者明確表達要查看回饋後才生成報告。系統 MUST NOT 在未經使用者回應的情況下主動送出報告內容。

#### Scenario: 使用者接受邀請

- **WHEN** 使用者點擊邀請訊息中的查看回饋按鈕
- **THEN** 系統開始生成該 session 的教練報告

#### Scenario: 使用者未回應邀請

- **WHEN** 使用者收到邀請後未做任何回應
- **THEN** 系統不生成也不送出任何報告內容

#### Scenario: 重複點擊同一邀請

- **WHEN** 使用者對同一個 session 重複點擊查看回饋
- **THEN** 系統送出已生成的報告，不重新生成

### Requirement: 教練報告的生成

系統 SHALL 以該 session 已記錄的行為訊號為資料來源生成報告，報告 MUST 包含摘要、做得好之處、可調整之處、改寫示範與下次可嘗試的方向。報告內容 MUST 能引用使用者在該次對話中的原句作為依據。

#### Scenario: 依訊號生成報告

- **WHEN** 系統為一個訊號完整的 session 生成報告
- **THEN** 報告包含五個段落，且其中的評價可回溯至該 session 的具體訊號與原句

#### Scenario: 訊號尚未就緒

- **WHEN** 系統要為一個訊號偵測失敗或尚未完成的 session 生成報告
- **THEN** 系統不以不完整的訊號生成報告，並保留該 session 可於訊號補齊後重新生成

#### Scenario: 一場對話一份報告

- **WHEN** 系統為某個 session 生成報告
- **THEN** 該報告僅涵蓋該 session 的內容，不合併其他場次

### Requirement: 報告的送達

系統 SHALL 將生成完成的報告送達使用者，送出 MUST 遵循既有的訊息長度限制與順序保證，並 MUST 記錄實際送達的時刻。

#### Scenario: 報告送達

- **WHEN** 報告生成完成且訊息視窗仍有效
- **THEN** 系統將報告依訊息長度限制切分後循序送出，並記錄送達時刻

#### Scenario: 送達時訊息視窗已逾期

- **WHEN** 報告生成完成但平台訊息視窗已逾期
- **THEN** 系統不呼叫平台發訊 API，保留該報告為已生成未送達，並記錄原因

### Requirement: 生成與送達失敗的可補救性

系統 SHALL 區分「已生成未送達」與「生成失敗」兩種狀態。已生成的報告 MUST NOT 因送達失敗而重新生成，以避免重複產生模型呼叫成本。補救 MUST 由使用者的明確動作（再次點擊查看回饋）觸發，系統 MUST NOT 在使用者未表達意願的情況下，僅因收到一則不相關的新訊息就主動補送——那則訊息與報告無關，使用者當下未必還記得先前的邀請，貿然送出會顯得突兀。

#### Scenario: 生成失敗

- **WHEN** 報告生成過程失敗
- **THEN** 系統不留下半完成的報告內容，並記錄失敗原因使該 session 可重新生成

#### Scenario: 已生成但送達失敗後重試

- **WHEN** 使用者在報告因視窗逾期而未送達後，再次點擊查看回饋的按鈕
- **THEN** 系統直接送出既有內容，不再次呼叫模型
