## MODIFIED Requirements

### Requirement: 使用者設定頁的存取

系統 SHALL 讓使用者在與共用角色的私訊中，以關鍵字「芝麻開門」取得一條專屬連結，點擊後進入自己對該共用角色的設定頁，不需另外註冊帳號密碼。連結 MUST 只對應到發出請求的那位使用者與那個共用角色，MUST 有時效，逾時即失效，並 MUST 只能在第一個打開它的瀏覽器上使用。使用者 MUST NOT 存取其他使用者的設定。

#### Scenario: 以關鍵字取得設定連結

- **WHEN** 使用者在私訊中傳送「芝麻開門」
- **THEN** 角色回覆一條該使用者專屬、有時效的設定頁連結，此訊息不觸發一般的角色回覆

#### Scenario: 連結逾時

- **WHEN** 使用者點擊已逾時的設定連結
- **THEN** 系統拒絕存取，並提示使用者重新在私訊中傳送「芝麻開門」

#### Scenario: 舊關鍵字當一般訊息

- **WHEN** 使用者在私訊中傳送「設定」
- **THEN** 系統把它當成一般聊天訊息，由角色正常回覆，不回覆設定連結

#### Scenario: 他人的連結

- **WHEN** 有人取得並開啟另一位使用者的設定連結
- **THEN** 只能進入該連結所屬使用者的設定頁，無法藉此存取其他使用者的設定

#### Scenario: 連結被轉貼到另一個裝置

- **WHEN** 連結已被某個瀏覽器打開後，另一個瀏覽器帶著同一條連結請求讀取、保存或恢復預設
- **THEN** 系統拒絕這些請求且不更動任何設定，並提示使用者重新在私訊中傳送「芝麻開門」取得新連結

#### Scenario: 原瀏覽器繼續使用

- **WHEN** 打開連結的那個瀏覽器重新整理頁面、保存或恢復預設
- **THEN** 系統照常處理，直到連結逾時

#### Scenario: 連結預覽不算打開

- **WHEN** Instagram 為了產生連結預覽卡片而抓取設定頁網址
- **THEN** 連結不被視為已打開，使用者點開時仍可正常使用

#### Scenario: 竄改連結

- **WHEN** 有人修改連結中的參數，試圖指向其他使用者
- **THEN** 系統拒絕存取且不洩漏該使用者是否存在
